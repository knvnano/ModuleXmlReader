# Этап 3 — исправления и проверка на эталонах NovaLCT

## Результат

Исправлены ошибки поворотов, состояния редактора, сохранения, валидации и предпросмотра.
Слоистая MVVM-архитектура сохранена: Application зависит от Domain, Infrastructure
и Presentation — от Application, а Avalonia собирает реализации. Внутренние слои
не зависят от UI или XML.
WinForms-проект и его решение не изменялись.

Проверки: 61/61 тестов успешно. Сборка Release: 0 ошибок, 0 предупреждений.
TRX: `ModuleXmlReader.CharacterizationTests/TestResults/stage3.trx`.

## Что установлено по присланным файлам

Источник — четыре файла `128_64_normal/90/180/270.module` и соответствующие
снимки окна Details Of Module. На снимках угол задаётся **по часовой стрелке**:
90° — вправо, 270° — влево. Копии XML включены в тестовые Fixtures.

Профиль: DP5135Common, DP32020, Concurrent, Scan_32, две группы данных.
В каждом XML 36 полей Module. Между вариантами изменяются семь функциональных
полей и Name. LineBias, RowsCtrlByDataGroup и StartPositionOfDataGroup не меняются.

| Поле | 0° | 90° | 180° | 270° |
|---|---|---|---|---|
| PixelCols × PixelRows | 128 × 64 | 64 × 128 | 128 × 64 | 64 × 128 |
| DataDirectType | Horizontal | Vertical | Horizontal | Vertical |
| PointTableData, пара i | (i, 0) | (31, i) | (127−i, 31) | (0, 127−i) |
| DataGroupSequence, активные группы | 0–1 | 1–0 | 1–0 | 0–1 |
| ScanABCDCode | 0…15 | 15…0 | 15…0 | 0…15 |
| NewScanABCDCode, активная часть | 0…31 | 31…0 | 31…0 | 0…31 |
| LineBias | 0 | 0 | 0 | 0 |

PointTableData содержит **128 пар X–Y**, а не массив из 8192 физических пикселей.
Размер базовой группы в исходном положении — 128 × 32. После 90° он равен
32 × 128. Поэтому геометрия определяется направлением и количеством групп.
NewScanABCDCode всегда содержит 128 значений: активные 32 и хвост из 96 нулей.
Ноль в активной части — полноценный адрес, его нельзя удалять как заполнение.

## Правила поворота

Для ширины w и высоты h **одной группы**:

- вправо: `(x, y) → (h−1−y, x)`;
- влево: `(x, y) → (y, w−1−x)`;
- 180°: `(x, y) → (w−1−x, h−1−y)`.

Порядок пар остаётся порядком тактов, маркер 255–255 остаётся на своём месте.
На 90° меняются размеры модуля и направление данных. На 180° они сохраняются.
При развороте оси размещения групп меняется порядок активных групп и адресов
сканирования; неактивные хвосты массивов остаются нетронутыми.
LineBias не пересчитывается по максимуму кода: эталоны прямо опровергают это правило.

## Исправления

| Проблема | Новое поведение | Проверка |
|---|---|---|
| Левый поворот заменял ввод фиксированными 64 парами | Преобразуются обе координаты каждой исходной пары по размерам группы | Все эталоны; ненулевой Y; обратимость |
| Правый поворот отбрасывал координату и терял 255–255 | Сохраняются число и порядок пар, пропуски и обе координаты | Все эталоны; пропущенная пятая точка |
| Менялись не все поля развёртки | Обновляются DataGroupSequence и активные части обоих кодов; LineBias сохраняется | Полное сравнение XML всех 12 переходов |
| Кнопка 180° не работала | Добавлена полноценная команда и преобразование на 180° | XML-эталоны, обратимость, UI-команда |
| Повороты перечитывали диск и теряли правки | Работают с текущим состоянием; документ хранится в памяти | Правки перед поворотом; изменение/удаление исходника |
| Ошибка открытия оставляла смесь двух файлов | Новый документ сначала загружается и проверяется отдельно, затем применяется целиком | Ошибки XML, таблиц, размеров, кодов, числа групп |
| Сохранение смешивало UI с изменившимся исходником | Сохраняется клон загруженного документа с текущими правками | Неизвестный вложенный XML и комментарии остаются |
| Запись могла повредить существующий файл | Сериализация во временный файл рядом с назначением, затем замена переименованием | Принудительный сбой после частичной записи |
| Отсутствующие редактируемые XML-поля молча пропускались | SetValue создаёт отсутствующие элементы | Удаление обоих кодов, редактирование и сохранение |
| Некорректный ввод можно было сохранить | Проверяются пары, байтовые значения, размеры, диапазон координат, TotalPointInTable и коды | Отрицательные/нечисловые значения, нечётные пары, границы, длины |
| Предпросмотр обрезался и читал числа вместо пар | Отрисовывается вся сетка в согласованном масштабе; используются координаты целых пар | Проверка пикселя за прежней обрезанной областью |
| После правок показывались устаревшие данные | Пропуски, подпись кода, ошибки и предпросмотр обновляются сразу | VM и двухсторонние UI-привязки |
| Save As оставлял старый путь | Путь меняется после успешной записи; признак изменений сбрасывается | VM и тест сохранения |

Если текущий ввод некорректен, предпросмотр очищается и выводится причина;
сохранение и повороты недоступны. Исходный документ и файл при этом не повреждаются.

## Дополнительно исправлено и улучшено

- Добавлено отслеживание изменений и подтверждение при открытии другого файла
  и закрытии окна: Сохранить / Не сохранять / Отмена. Отмена диалога сохранения
  или ошибка записи сохраняет редактор открытым с правками.
- Команды блокируются на время операции; повторное нажатие не открывает второй
  диалог и не запускает параллельный поворот. Ошибки файлового диалога показываются
  пользователю без аварийного завершения обработчика.
- На снимке загруженного окна выявлено растягивание разметки длинной строкой
  таблицы: кнопки уходили за экран. Исправлены ограничения ширины и прокрутка;
  положение кнопки и редактора проверяется автоматически.
- Показаны текущий путь и индикатор изменений. Начальные значения параметров
  очищены от декоративных надписей вроде `Name:` в столбце значений.

## Архитектура после исправлений

- Domain: PointTableEntry, ModuleGeometry, ValidatedModule, PreviewData, Rotation,
  ModuleEditorState. Графических и XML-типов нет.
- Application: строгий PointTableParser, ModuleValidationService, преобразования
  координат/кодов, предпросмотр и транзакционное применение состояния редактора.
- Infrastructure: клонирование полного XML, создание полей и безопасная запись.
- Presentation: команды, наблюдаемые свойства, состояние изменений и политика
  подтверждения закрытия/открытия; только интерфейсы платформенных сервисов.
- Avalonia: AXAML, отрисовка, диалоги и адаптация события Closing к ViewModel.
  Вычислительных алгоритмов и файлового ввода/вывода в окнах нет.

Нормативные тесты, которые требовали воспроизводить ошибки первого этапа, удалены.
История старого поведения остаётся в отчётах этапов 1 и 2 и в исходном WinForms-коде.

## Проверки и ограничения

- 12 переходов: из каждого из четырёх файлов поворот на 90°, 180°, 270°.
  Сравнивается **весь XML** с эталоном назначения, исключая только Name:
  редактор сохраняет имя исходного модуля, а не генерирует новое имя по углу.
- Четыре последовательных поворота и обратные повороты возвращают исходные данные.
- Геометрические тесты используют также ненулевой Y и другую прямоугольную группу.
- Проверены валидация, отказ записи, сохранение неизвестных данных, MVVM,
  подтверждения несохранённых правок, границы слоёв и отрисовка через Headless/Skia.
- [Актуальный интерфейс](screenshots/editor.png).

Подтверждённое соответствие NovaLCT относится к присланному профилю.
Для других типов драйверов/развёртки нужны дополнительные эталоны. Поддерживаются
обычные равные прямоугольные группы (1–8), байтовые координаты и Scan_N до 128.
Неравные группы, неизвестный ScanType и некорректные последовательности групп
не преобразуются молча: операция завершается сообщением без изменения документа.

Предпросмотр показывает координатную трассу PointTableData, повторённую по группам,
а не симуляцию всех тактов электрического сканирования. Для пары 255–255 координаты
отсутствуют; её номер показывается в списке пропусков.
Импорт сгенерированных файлов в запущенный NovaLCT и проверка на оборудовании
не выполнялись. Нативные файловые диалоги проверены через их интерфейсы в тестах.

```powershell
dotnet build ModuleXmlReader.Avalonia.sln -c Release
dotnet test ModuleXmlReader.CharacterizationTests/ModuleXmlReader.CharacterizationTests.csproj -c Release --no-build --logger "trx;LogFileName=stage3.trx"
```
